- **Edge process globals (2026-08-20, `.specify/specs/edge-process-globals/`)**
  — the three edge singletons (routing table, forwarder, control plane)
  are now `'static` `OnceCell` process globals instead of injected
  `Arc`s threaded through an `AppState`. `AppState` deleted; HTTP
  handlers read the globals directly; `signup`/`delete` take no
  table/forwarder params; `rehydrate` stays a param'd recovery
  primitive (it runs during init, before the table global is
  published). `init_globals()` hydrates all three from Redis via
  `get_or_try_init` before any is visible — a boot that can't reach
  Redis returns `Err`, not a crash. Test seam: `OnceCell::set()` pre-seeds
  an instance, bypassing hydration. `app.rs` (client) untouched. Per
  the lifetimes principle in `writing/human/lifetimes_in_rust.md`:
  process-lifetime data belongs in `&'static`, not `Arc`. Proof:
  `cargo test` 121/121 **with** the live Redis round trip (previously
  skipped for lack of REDIS_URL); `cargo build --bins` both binaries.
- **Edge identity install split (bug fix, same proposal)** — the edge
  WG private key is now installed into `wg0` **once at boot**
  (`install_edge_identity`), not on every `signup`; `edge_public_key()`
  is a pure getter. Fixes a latent bug the live Redis round trip
  surfaced: `signup()` called `edge_public_key()` per signup, which
  reinstalled the key each time (`set_private_key` per signup). Proof:
  `redis_store_round_trip` asserts `private_keys.len() == 1` after two
  signups.
- **DNS on signup (2026-08-21, `.specify/specs/dns-on-signup/`)** — the
  control plane provisions per-customer AAAA records at runtime:
  - `DnsApiClient` trait (`controlplane/dns.rs`, mirrors `WgClient`):
    `upsert_aaaa(name, ipv6)` / `remove_aaaa(name)`, one record per
    call, full name, typed IPv6. Real client `HetznerDns` (zone_id,
    zone_name, token as `'static` `LazyLock` config from env — the
    provider's own config, nothing about naming). Static config
    global + `get_dns_api() -> &'static dyn DnsApiClient`;
    `ensure_dns_config()` fails boot on missing env.
  - `DOMAIN` is a **separate** global (naming layer, above the
    provider). Orchestrator `upsert_customer`/`remove_customer` build
    `{username}.{DOMAIN}` + `*.{username}.{DOMAIN}`, upsert both
    concurrently.
  - Resolution is independent: `resolve_aaaa` (hickory-resolver, fixed
    1.1.1.1 resolver). A background **reconcile loop** in `edge.rs`
    verifies both records per customer against real resolution and
    re-applies mismatches — first pass ~30s after boot, then every 2h.
  - **Username IS the customer id** — `Customer.id` replaced by
    `username`; Redis key `CUST_KEY{username}`, structural uniqueness
    (`SETNX` collision → 409). `POST /signup` takes
    `{"username":"bob"}`, validates as a DNS label, creates both AAAA
    records (non-fatal last step — the reconcile loop self-heals),
    returns `hostname`. `DELETE /customers/:username` removes records
    (best-effort; stale-record-on-outage logged loudly).
  - **`ControlPlane` de-Arc'd** per `writing/human/lifetimes_in_rust.md`:
    dropped `#[derive(Clone)]`; `subnet`/`wg_subnet` owned;
    `wg`/`dns` are `&'static dyn` (real clients as statics; tests
    `Box::leak` their mocks and hold the reference to inspect).
  - Deps added: `reqwest` (rustls — the crate's first outbound HTTP),
    `hickory-resolver`, `async-trait`.
  - Edge systemd unit gained `EnvironmentFile=/etc/cococoir/dns.env`;
    `provision-edge.sh` writes it (zone_id + domain from tofu outputs,
    token = the same Hetzner token). New tofu outputs `dns_zone_id` +
    `domain`.
  Proof: `cargo test` 132/132 **with** live Valkey round trip (2 signups
  → 4 DNS upserts, delete → 2 removes, hostname fields, username keys);
  `cargo build --bins`; edge systemConfig evals with the
  EnvironmentFile; `tofu validate` green.
